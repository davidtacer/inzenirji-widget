| ADR-012 | 2026-10-13 | Accepted | Night plan while the owner sleeps (owner: "naredi vse, da bom zjutraj testiral delujočo verzijo"): (1) the site template is built inside this monorepo (`apps/site` + `packages/site-schema`) until it gets its own repo; this also answers ADR-007 for now — the block/content schema is the shared package `@inzenirji/site-schema`; (2) a demo client site uses this repo as its "client repo": content edits go to branch `demo/dev`, publishing merges into `demo/main`; workflow `site-demo.yml` deploys `demo/dev` to `https://demo-dev.inzenirji.si` (hidden test site) and `demo/main` to `https://demo.inzenirji.si`; (3) for dev the API writes to GitHub with a fine-grained token (`GITHUB_TOKEN` Worker secret, Contents read/write on this repo only); per-client GitHub App comes with real clients; (4) agent tools replace whole page/site JSON (`write_page`, `write_site`) instead of JSON Patch — simpler and robust for small pages, slightly more output tokens. | Lets the owner test the whole loop (chat → change on test site → publish → undo) with three secrets and no new repos. | ADR-013 | 2026-10-14 | Accepted | **Each site publishes its own content schema** (supersedes the "shared package" part of ADR-012 and answers ADR-007). Every client repo defines its editable content in code (zod in the site's own `schema/`) and commits the generated `<contentRoot>/schema.json` (`{ version: 1, notes?, site, page }`, JSON Schema draft 2020-12). The editor knows no block types: it reads `schema.json` from the site's branch on every edit, gives it to the agent and validates every write against it (Workers-safe validator, no `eval`). The site build validates the same content again with its zod schema (second gate). Blocks are designed per site; `@inzenirji/site-schema` is only a starter kit for new sites. The rules every site must follow are in `docs/guides/site-contract.md`. | Owner 2026-10-14: every site is unique ("ne želim da smo omejeni glede na vsebino in obliko") and sites are built by us to our standards. A schema per site keeps that freedom while keeping the safety (the agent can only write what the site's schema allows, the design stays in code). Old sites keep their schema version. Trade-off: a new kind of section still needs a developer (component + schema), which is intended. |
