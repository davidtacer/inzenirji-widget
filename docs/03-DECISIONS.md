Rounding up is never in our disfavour and is shown to the client before publishing. |
| ADR-006 | 2026-10-13 | Open | Hosting of client sites and of widget/API: Cloudflare (Pages/Workers) vs. own server (Hetzner). | Owner decision pending. Code stays runtime-agnostic (Web standard Request/Response via Hono) until decided. |
| ADR-007 | 2026-10-13 | Open | Where the content/block schema lives: in the site template repo (API reads it from each client repo) or in a shared package used by both. | Proposed answer: each client repo is the source of truth (`src/schema/` exported as JSON Schema at build time); the API reads it per site, so old sites keep their own schema version. Decide together with phase 0. |
| ADR-008 | 2026-10-13 | Proposed | Auth across the iframe: magic link to `<site>/uredi#token=…`, embed passes the one-time token to the iframe via `postMessage`, widget exchanges it for a bearer session token kept in memory/partitioned sessionStorage. No third-party cookies. | Third-party cookies in iframes are blocked (Safari) or partitioned (Chrome). This flow works in all major browsers without cookies. Implemented in the auth task. |
| ADR-009 | 2026-10-13 | Accepted | Hosting on Cloudflare (supersedes ADR-006 "Open"): client sites on Cloudflare Pages; widget + API as one Worker with static assets on `uredi.inzenirji.si` (dev: `uredi-dev.inzenirji.si`); data in D1; screenshots via Browser Rendering. Start on the free plan, move to Workers Paid (5 $/month) before the first real client. Deploy from GitHub Actions with wrangler. | Owner decision 2026-10-13. `inzenirji.si` is already on Cloudflare. Free-plan limits that matter: Pages 500 builds/month and 1 concurrent build per account, 100 Pages projects per account; Workers Free 10 ms CPU per request; Browser Rendering 10 min/day. Revisit at ~100 clients or when builds become the bottleneck. |
| ADR-010 | 2026-10-13 | Accepted | Auth details (completes ADR-008): login links valid 15 min, single use, sent only to e-mails registered for the site; sessions 30 days, revocable, bound to one site; tokens are 32 random bytes, stored only as SHA-256 hashes; limits 5 login mails/hour per site+e-mail, 20/hour per IP, 30 exchanges/hour per IP; login request always answers 202 and sends in the background. E-mail via the owner's SMTP (`hello@inzenirji.si`, `mail.datavallis.com:465`) using `worker-mailer` over Cloudflare TCP sockets. Local dev runs the real Worker (`wrangler dev` + local D1); the Node entry and runtime-agnostic requirement are dropped. | Owner chose own SMTP (2026-10-13). 30-day sessions because owners edit from a phone and a new magic link each day would annoy them; removal from `site_users` revokes immediately. One runtime everywhere avoids D1/SMTP shims. Supersedes ADR-003's "Hono on Node" part. |
| ADR-011 | 2026-10-13 | Accepted | Every client site's `/uredi` page follows `docs/template/uredi-page.md`: hidden from search engines (`noindex, nofollow` meta and `X-Robots-Tag`, `Disallow: /uredi` in robots.txt, not in the sitemap, not linked) and without header/footer/cookie banner so the editor iframe has the whole screen. | Owner decision 2026-10-13. The header is added because `Disallow` alone hides the page's `noindex` from crawlers that respect robots.txt. |
